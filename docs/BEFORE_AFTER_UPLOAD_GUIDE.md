# Before / After施工事例 追加ガイド

## 目的

既存ホームページの施工事例を壊さず、施工前・施工後の2枚を1組として追加します。
この仕組みはローカルで公開データを準備するもので、実行しただけではGitHubへの送信やホームページ公開は行いません。

## 写真を追加する前の確認

- お客様からホームページ掲載許可を得る
- 顔、表札、車のナンバー、住所が写っていないことを確認する
- BeforeとAfterが同じ方向から撮影されているか確認する
- 横長写真を推奨する。画像形式は jpg / jpeg / png / webp

## 追加方法

プロジェクトのフォルダーで次の形式を実行します。

```sh
npm run case:add -- \
  --slug "toyohashi-example" \
  --title "【豊橋市】雑草のお庭を人工芝へ" \
  --description "雑草対策とお子様の遊び場を両立した施工事例です。" \
  --date "2026-08-23" \
  --area "豊橋市" \
  --before "/写真フォルダー/施工前.jpg" \
  --after "/写真フォルダー/施工後.jpg" \
  --cost "約30万円" \
  --period "2日間" \
  --tags "雑草対策,人工芝" \
  --concerns "草むしりの負担を減らしたい" \
  --voice "庭で遊べるようになりました" \
  --points "下地を丁寧に転圧|高耐久防草シートを施工"
```

必須項目は `slug`、`title`、`description`、`date`、`area`、`before`、`after` です。
同名の記事または画像がある場合は上書きせずに中止します。

任意項目は `cost`、`period`、`tags`、`concerns`、`voice`、`points`、`body` です。
`body` は記事の本文になります。省略すると「施工内容を確認して追記してください。」が入ります。

## iPhoneアプリから受け取った場合

谷口さんのiPhoneアプリ「リラガーデン」から、写真2枚と掲載用の文章が届きます。
届いた文章には、上と同じ形式のコマンドがそのまま入っています。

1. 届いた写真2枚をMacへ保存する（既定では `~/Downloads`）
2. `relagarden-website` のフォルダーで、届いたコマンドを貼り付けて実行する
   - 写真を別の場所へ置いた場合は、`--before` と `--after` のフォルダー部分だけ直す
3. `npm run build` と `npm run dev` で見た目を確認する
4. 問題なければ `main` へ反映する（反映すると自動でホームページへ公開されます）

アプリはGitHubにもXserverにも接続しません。認証情報も持ちません。
公開するかどうかは、必ずこの手順で人が判断します。

## 公開前の確認

1. `npm run build` が成功することを確認する
2. `npm run dev` で施工事例一覧と詳細を目視確認する
3. Before / Afterの向き、説明文、地域名、金額を再確認する
4. 確認後に担当者がGitHubへ反映する

## 役割分担

- 谷口さん: 写真選択、地域、金額、工期、施工内容を入力
- アプリ: 写真の位置情報を除去し、掲載用コマンドを作る
- ホームページ担当者: 内容確認、GitHub反映、公開確認

## 公開までの経路

```text
iPhoneアプリ
  → 写真の書き出し（位置情報を除去）＋ 掲載用コマンドの作成
  → 担当者へ送付
  → Macで npm run case:add を実行
  → 内容確認（npm run build / npm run dev）
  → GitHub main へ反映
  → GitHub Actions が Astro をビルドして Xserver へ配置
  → ホームページに公開
```

アプリからGitHubやXserverへ直接書き込む経路は作りません。
GitHubトークン、Xserverの認証情報、パスワードをアプリへ埋め込まない設計を維持します。
公開前確認と上書き防止も維持します。
